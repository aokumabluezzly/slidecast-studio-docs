GAS UPDATE GUIDE

How to update SlideCast Studio

Move the Apps Script edition to the latest version, keeping the same URL and the same data

  • Apps Script edition
  • Same URL
  • Data carried over
  • About 5 minutes
  • Beginner friendly
aokuma2026.07.21Apps Script edition

🔄 OVERVIEW

What this page covers

If you run SlideCast Studio on Google Apps Script, this page explains how to move to a new version.

Done this way, the slides you have already made, your library and your settings all carry over, and the URL you have bookmarked stays the same.

🔗

The URL doesn’t change

You update the existing deployment, so your bookmark keeps working.

💾

Your data stays

Projects, asset library and settings remain available in the same browser.

📄

It’s just a swap

Paste two HTML files over the old ones and redeploy.

⚠️ Back up first, always

Step 1 saves a backup. Do not delete the old version until the backup is saved and you have confirmed everything came across.

💡WHYWhy swapping the files is the better route

You could copy the whole new version from the shared drive, but that costs extra work and brings a few drawbacks.

SlideCast Studio itself runs as an Apps Script project on Google Drive. The projects, library, settings, images, audio and video you create are stored in your browser’s storage.

So as long as you open the same URL in the same browser and the same browser profile, your earlier data is still there. It will not appear automatically on another computer or in another browser — there you have to restore from a backup.

BEFORE

Copying the whole thing: you get a new Apps Script project, so the URL changes and your earlier projects and settings do not appear on their own. You have to save a backup in the old version and restore it in the new one.

AFTER

Swapping the files: the URL stays exactly as it was, and the slides and settings already stored carry straight over.

  • A full copy means a new URL, and extra backup-and-restore work
  • Browser data from environments you no longer use can linger
  • A small amount of it has almost no effect on your computer
  • Lots of images, audio and video do take up storage, which can affect saving, loading and backups

To avoid all of that, the recommended route is to swap only the files inside the project you are already using, and stay on the same project.

Step by step

1. Save a backup, just in case

Open the SlideCast Studio you are using now and save a backup from “Save data” on the dashboard. If you want the library to come across as well as your projects, tick the items you need on the backup screen.

2. Open the Apps Script project you use today

Open the Apps Script editor for your current project, either from the project list on script.google.com or from Google Drive.

3. Replace the contents of 無題.html with the new version

Open 無題.html from the file list, select everything (Cmd / Ctrl + A), delete it, and paste in the contents of the new version’s 無題.html.

The file names come from the Japanese Apps Script UI: 無題.html is “Untitled.html” and コード.gs is “Code.gs”. Whatever they are called in your editor, the position in the list is the same.

4. Do the same for AppBundle.html

Open AppBundle.html, select all, delete, and replace it with the new version in the same way.

5. Replace any other files the release notes mention

Usually only 無題.html and AppBundle.html need updating, but if the release post says so, replace コード.gs or other files the same way.

6. Save

Once the files are overwritten, save.

7. Open “Deploy” → “Manage deployments”

Press “Deploy” at the top right and choose “Manage deployments”.

8. Press the pencil (edit) icon on the existing deployment

On the “Manage deployments” screen, click the pencil (edit) icon to the right of the deployment currently in use.

9. Set Version to “New version”, then press “Deploy”

From the Version dropdown choose “New version”, then press “Deploy”.

10. Done

Press “Done” and that is it. The web app URL shown is the same one as before.

✅ That’s the update finished

Your project is the same project; only its contents are now the latest version.

⚠️WATCH OUTPick “New version”, not “New deployment”

This is the single easiest thing to get wrong.

When you deploy, the route to take is “Manage deployments” → edit the existing deployment → “New version”, not “New deployment”.

Even inside the same project, choosing “New deployment” issues yet another URL, and the slides and data stored there are treated as a separate set.

BEFORE

❌ New deployment → a new URL is issued (and the data is treated separately)

AFTER

⭕ Manage deployments → edit the existing deployment → New version → the URL stays the same, and the data saved in that browser is still there

⚠️ Nothing shows up on another computer or browser

On a different computer, browser or browser profile, your data will not appear automatically. Restore from a backup there.

🧩GOING FURTHERMerging several projects into one

What to do if you already built the new version on a separate URL, or if unused versions are still lying around.

To bring projects or libraries from a version you no longer use into one place, save a backup from the SlideCast Studio dashboard and restore it in the copy you intend to keep.

  • Once the move is complete, the old project can be deleted
  • After restoring, check that projects, images, audio, video, library and settings all came across
  • Do not delete the old version until that check is done

Clearing out data from the old environment

Once the move is finished, you can clear the browser data of the old environment from “Reset data” on the old version’s dashboard.

⚠️ Resetting data cannot be undone

Save a backup and confirm that restoring works before you run it.

Deleting the old Apps Script project from Google Drive

After the move to the new version is complete, an Apps Script project you no longer need can be sent to the trash from Google Drive or from the Apps Script project list.

  • Deleting the Apps Script project makes its web app URL unusable
  • Don’t delete anything until the backup and the move are confirmed
  • Right after a move, leaving the trash unemptied for a while is the safer choice
  • Deleting the Apps Script project does not necessarily delete the project data held in your browser
  • An Apps Script project is tiny, so deleting it will not noticeably speed up your computer
🙌FINALLYFinally

When you update, please use the route described here — swap the files, then deploy a new version of the existing deployment — rather than copying the whole thing from the shared drive.
